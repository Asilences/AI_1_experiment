# P0冻结语义问答使用说明

P0是独立的免训练试验模式：冻结指令模型解释问题，受控图谱工具执行查询，再依据证据生成答案。A0/B0主实验、旧模型和冻结数据保持各自版本。P0仍有计划错误；它的20题开发验收不能替代独立自然问题测试。

## 准备目录与模型

从当前源码运行，Python使用项目内`.venv`。需要独立的`data/processed/movies_v2_20261030/`目录。原开发验收的冻结版本已发布到[submission-assets-20261031](https://github.com/Asilences/AI_1_experiment/releases/tag/submission-assets-20261031)，无需依赖作者本机缓存或重新在线采集。

`catalog_v2-frozen-20261031.zip`为19445265字节（约18.54 MiB），含6个冻结文件、5000电影与170516条声明，解压约322.65 MiB。SHA-256为`5b355f0e5328d8187767419d6a529d27b28b1deb2279a8a4abcc17eac14c3963`。完整文件清单与逐文件校验值见[manifest](../configs/submission-assets-20261031.json)。

```powershell
.\.venv\Scripts\python.exe -m kgqa.submission_assets install --asset catalog_v2 --project-root H:/AI1experiment --proxy http://127.0.0.1:7890
.\.venv\Scripts\python.exe -m kgqa.submission_assets verify --asset catalog_v2 --project-root H:/AI1experiment
```

代理非必需，无代理时去掉`--proxy`。下载缓存位于H盘项目`.work/submission-assets/`，归档解到项目相对路径；程序核对归档与逐文件SHA，拒绝覆盖不同版本文件。可用`--archive <已下载ZIP路径>`从本地包恢复，或把`--project-root`指向全新目录验证。在线重新采集/补名应生成新版本，不能保证恢复这份原冻结数据；数据覆盖和重采方法见[V2实施与验收](V2工具问答实施与验收.md)。

模型服务需要含PyTorch和Transformers的完整环境；客户端协议、工具和CI无需下载模型。示例从源码根目录下载固定revision到H盘独立目录：

```powershell
.\.venv\Scripts\python.exe scripts/prepare_frozen_llm.py --destination H:/AI1experiment/.work/p0-model/Qwen2.5-3B-Instruct
.\.venv\Scripts\python.exe scripts/serve_frozen_llm.py --model-dir H:/AI1experiment/.work/p0-model/Qwen2.5-3B-Instruct --gpu-memory-fraction 0.25 --port 7870
```

固定模型为`Qwen/Qwen2.5-3B-Instruct`，revision为`aa8e72537993ba99e69dfaafa59ed015b17504d1`。下载脚本另有`--proxy`参数。本机内存或显存不足时使用远端独立服务；服务器环境和GPU共享约定见[服务器说明](服务器与训练运行说明.md)，不要直接套用本机CUDA依赖或重复启动已有服务。运行前检查GPU；本项目已有GPU1共享授权，PyTorch分配器上限25%、CPU线程2，不能停止其他任务。

若复用已启动的远端服务，在单独本机终端建立回环隧道并保持运行：

```powershell
ssh -N -L 7870:127.0.0.1:7870 -p 50012 junjiex@222.20.94.68
```

模型服务与Web界面只监听回环地址；隧道本机端口已占用时先核查现有进程。

## 启动并查看问答

本机另开终端，在项目根目录运行：

```powershell
$env:KGQA_LLM_BASE_URL = 'http://127.0.0.1:7870/v1'
$env:KGQA_LLM_MODEL = 'Qwen2.5-3B-Instruct'
.\.venv\Scripts\python.exe -m kgqa.web --catalog-dir data/processed/movies_v2_20261030 --port 7864 --open
```

浏览器访问`http://127.0.0.1:7864/`，切换至“P0自然语言图谱问答”。可尝试`Who put together the screenplay for Inception?`或`《盗梦空间》的导演还拍过哪些片？`，查看计划、原始模型输出、实际结果、声明证据和模板回退标记。模糊片名先确认候选；服务错误会明确显示，不用规则答案冒充P0。

CLI可单独保存结果，输出目录应为本次独立路径：

```powershell
.\.venv\Scripts\python.exe -m kgqa.semantic_qa --catalog-dir data/processed/movies_v2_20261030 --question 'Who put together the screenplay for Inception?' --output output/p0-demo/result.json
.\.venv\Scripts\python.exe scripts/evaluate_semantic_dev.py --help
```

## 支持范围与开发结果

工具具备单/多电影多属性、实体交集、导演反查与有限金额比较能力；冻结模型能否正确规划需逐题检查。日期过滤、计数、剧情与推荐等尚未开放，缺事实不推断为否定事实。长列表及复杂类型可能直接采用证据模板，回退单列。

本轮审计将最终展示改为`render_tool()`生成的受控完整证据句，模型自由文本只保留在`raw_answer`供查看。只有与证据句仅空白不同、引用完全匹配时标记accepted；单有正确名称与引用不再放行任意句子。它约束回答呈现，不能修正错误计划或图谱事实。合成控制器测试覆盖关系错写、主客体颠倒和附加获奖断言，不冒称真实Qwen错误样例。

20题开发验收中英各10题、仅两部电影：D0/P0计划匹配分别为12/16与7/16，结构任务匹配12/20与10/20，状态匹配12/20与14/20；P0回退11/20。P0平均单题约5.95秒，包含模型服务与网络开销。原题、配置、逐题输出和数据来源哈希见[开发记录](../verification/2026-10-31/semantic_p0/dev_v1/)。这些是已用于诊断的程序编写开发题，尚无独立泛化与人工文本评分结论。

以上11/20为旧控制器真实开发运行值。新控制器对同批保存输出的[离线重放](../verification/2026-10-31/pr12_audit_fixes/p0_guard_replay/summary.json)回退13/20，拦下原accepted中的2条；没有调用模型、重新执行计划或测延迟。显存纠正：实际本账户P0服务PID三次采样均7542 MiB，约7.37 GiB，非全生命周期峰值；原2.1—2.5 GiB说法撤回，见[采样记录](../verification/2026-10-31/pr12_audit_fixes/p0_memory.json)。
