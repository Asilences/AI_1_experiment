## 下载与环境

在 GitHub 的本次拉取请求中选择 **Files changed** 查看改动，或打开其源分支，通过 **Code → Download ZIP** 下载。解压后进入包含 `kgqa`、`tests`、`requirements-test.txt` 的项目根目录。

推荐 Python 3.11 或 3.12。在 PowerShell 中执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m kgqa.acceptance --output-dir output/acceptance/review
```

安装依赖需要网络；后面的验收在 CPU 上离线运行，不下载数据和模型。验收拒绝覆盖已有目录。复核时将 `review` 改为新的目录名，或省略整个 `--output-dir` 参数。

## 成功时查看什么

终端最后显示 `PASS synthetic offline acceptance`，退出码为 0。产物位于 `output/acceptance/review/`：

| 文件 | 查看内容 |
|---|---|
| `summary.json` | `status` 为 `PASS`，`checks` 全部为 `true`，包含模型与数据的相对位置 |
| `examples.json` | 导演、类型、国家、语言、多答案、别名和拒答的实际回答与事实证据 |
| `runs/A0_acceptance/metrics_test.json` | 30 道夹具测试的覆盖与自动指标 |
| `runs/A0_acceptance/validation_thresholds.json` | 只用验证集选择阈值的记录 |
| `runs/A0_acceptance/sensitivity_comparison.csv` | 同一模型在五组配置下各三次推理的对照 |

夹具共有 10 部虚构电影、150 道题，电影划分为 6/2/2，问题划分为 90/30/30。验收同时核对模型重载后的预测一致性、未知片名拒答及别名配对比较。失败时输出 `FAIL`、返回非零退出码，已创建目录中的 `summary.json` 记录失败检查。

GitHub 上打开 **Actions → CI**，选择本次提交。Ubuntu 和 Windows 两个任务均应成功；任务日志中的“运行核心测试”和“离线训练与问答验收”可以分别查看测试数和 `PASS`。

## 现场问答演示

先运行上面的离线验收，再执行以下命令。去掉 `--question` 及其内容可以进入交互输入。

```powershell
.\.venv\Scripts\python.exe -m kgqa.demo --system a0 --data-dir output/acceptance/review/data/processed --model-path output/acceptance/review/runs/A0_acceptance/model.pkl --question "Who directed Juniper Trail?"
```

应显示电影实体、P57 关系、事实证据和完整句回答。也可询问 `What genre is Lunar Garden?`、`Who directed Trail of Juniper?`；询问 `Who directed Zyxwuv Qpkjrt?` 应拒答。名称属于验收夹具。

已有正式个人运行时，可以直接使用自己的模型，不必复制到共享的 `models/pipeline`：

```powershell

```

此命令需要对应的真实数据和本机模型；代码下载包不包含它们。原 `both` 模式还需要队友的神经检查点与验证选模记录。
