# A0、B0与标准测试满分现象

核查日期：2026-10-31。本说明针对第一阶段四关系电影问答，不把新V2工具目录和旧实验混为一份结果。

## A0、B0分别是什么

这些是本项目的实验编号，不是行业统一的模型名称；`0`表示该方法的基础配置。

| 编号 | 实现 | 实际学习/推理过程 |
|---|---|---|
| A0 | 管道式基线 | 字典/别名及近似匹配链接电影；词与字符TF-IDF＋逻辑回归分类关系；按电影和关系查询本地事实；用固定句式组织答案。需要训练关系分类器，但答案本身不由生成网络写出。 |
| B0 | 神经生成基础配置 | 共用电影链接入口，取该电影的可见三元组文本和冻结TransE向量；三元组向量拼接后投影成前缀，与问题/事实文本输入FLAN-T5-small，生成完整答案。基础学习率1e-4、5 epoch、名义有效batch 16、seed42。 |
| B1/B2/B3 | B0学习率对照 | 分别为3e-5、3e-4、1e-3；其他设置按同一轮配置保持一致，从共同初始模型训练。 |
| C0 | 图嵌入消融 | 保留相同事实文本，去掉TransE结构前缀，学习率1e-4。 |

B0的“生成”指问题＋检索子图→答案，检索前处理保持固定。它不是不查资料的闭卷模型，也不负责所有上游实体链接。微batch随数据轮次不同：200部实验为4×累积4；同伴5000部实验为8×累积2，均名义有效16。

## 为什么标准测试会出现100%

本轮重新加载正式发布的5000部A0模型，向`PipelineQA.predict`仅传入每条问题字符串，实际运行全部8917题。答案实体集合和文本与原保存预测均零差异；重算实体准确率、Macro-F1、BLEU、ROUGE-L与原指标差异均为0。

具体原因有三项：

1. **测试的是已知知识库查询。** 测试中8106道可回答题的标准实体集合全部存在于系统可见的本地知识库。A0只需正确链接电影、判断关系，再读取现成事实。它不需要推断没见过的事实。
2. **问题模板完全共享。** 训练/验证/测试电影分别3500/750/750，电影集合交集为0，原始完整问句的训练/测试交集也为0；但替换标题后，测试的15种模板全部在训练中出现。包括12种四关系问法和3种不可回答问法。这是新电影上的相同问法，不是未见自然表达泛化。
3. **答案格式也完全共享。** `kgqa.prepare`用`answer_text`生成参考答案，A0查询后同样调用`answer_text`。本次8917条输出都逐字等于一条参考答案，因此BLEU和ROUGE-L也满分。BLEU保存值100.00000000000004属于浮点尾差。

完整复算：[recomputed.json](../verification/2026-10-31/a0_audit/recomputed.json)。参考答案来自Wikidata快照及程序化模板，不是由模型输出反向生成，但也不是独立人工核查的自然问答金标准。

扩展构建还把歧义片名补成年份/QID形式，并检查标准题标题都能正确链接。例如历史`City on Fire`在5000版问题中写为`City on Fire (Q166734)`。这进一步降低了标准链接难度，所以不能把旧1000版到新5000版的分数变化当成开放问法泛化提升。

## 为什么几个参数设置也全是100%

A0这里改变的是**关系置信度的拒答阈值**，不是生成模型学习率，也没有每个阈值重新训练。可回答测试题的关系置信度为`0.9973375741—0.9987837391`，所以0.30、0.70、0.90、0.99都低于所有这些分数，不改变任何可回答题的决策。该分数也不能直接解释为经过校准的事实正确概率。

本次从保存的逐题置信度重放，结果如下，并与同伴分支的真实追加运行记录一致：

| 阈值 | 全部8917题实体集合准确率 | 误拒答/8106道可回答题 |
|---|---:|---:|
| 0.30/0.70/0.90/0.99 | 100.00% | 0 |
| 0.995 | 100.00% | 0 |
| 0.998 | 84.12% | 1416 |
| 0.999 | 9.09% | 8106 |

0.999时所有可回答题都被拒答，剩下的811道本来不可回答题贡献9.09%；可回答子集准确率实际为0%。因此它不是较好的设置。默认0.30仍由原验证流程决定，追加高阈值是看到饱和后的诊断，不能称作预注册泛化实验或用来重选默认阈值。

## A0并非所有测试都是100%

| 数据/场景 | 实体集合准确率 | 结果性质 |
|---|---:|---|
| 历史1000部标准测试 | 98.71%，1855题 | 保存的历史指标；本次没有重训或覆盖。 |
| 独立200部标准测试 | 100%，370题 | 保存的同模板受控测试；当前仓库缺该200部完整QA，不能用本机1000部默认数据冒配复算。 |
| 独立200部改写 | 75/100 | 固定扰动诊断，非独立真人自然提问集。 |
| 独立200部错拼 | 85/100 | 与同源原题比较。 |
| 独立200部别名 | 47/47 | 仅47条有可用别名的子集，分母不是100。 |
| 独立200部阈值0.99 | 9.19%，370题 | 保存的高阈值诊断；336道可回答题全被拒答，只有34道不可回答题正确。 |
| 正式发布5000部标准测试 | 100%，8917题 | 本次已重新加载模型实际复现，并复算保存预测。 |

不能把不同快照、不同阈值、不同评分版本的结果连成同一条提升曲线。A0事实分数默认读取系统返回的实体ID；原B0分数需从生成文本解析实体。分析比较时应同时报告文本评分、ID解析规则和原始生成文本；同伴PR #10的统一解码v2及固定名称恢复是另有记录的方法，不能套用为旧v1的原始分数。

## 这些结果能支持什么，后续如何评测

现有证据支持“固定图谱、共享模板上的检索与回答流程可以稳定运行”。它没有证实任意中英文自由提问100%正确，也没有单凭满分证明A0全面优于B0或TransE融合有效。事实在检索库中可见符合此任务定义；如果把结论换成未知事实预测，必须另做隐藏事实的任务和划分。

下一轮应保留现有分数，增加独立收集的自然问题、未见问法模板、残缺/同名片名、库外问题、多属性及条件问题；先按数据协议划出开发集和冻结测试集，再调规则或模型。分开统计实体链接、关系/计划识别、答案事实、拒答及证据支持，避免只报一个总分。无需为使曲线下降而人为破坏答案或改评分。
